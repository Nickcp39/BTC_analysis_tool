# 机会层插件规范 V1

## 1. 文档目的

定义机会层插件的开发规范，使得：

- BTC 周期分析是第一个插件
- NVDA 估值分析可以作为第二个插件接入
- 未来任何标的，只需按规范写插件，就能接入决策系统
- **内部分析逻辑完全自由，输出格式严格统一**

---

## 2. 核心原则

### 2.1 内部自由，接口统一

```
┌─────────────────────────────────────────────────────────┐
│                    机会层插件                              │
│                                                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │
│  │ BTC 插件     │  │ NVDA 插件    │  │ ETH 插件     │     │
│  │             │  │             │  │             │     │
│  │ 周期退火     │  │ DCF估值      │  │ 链上数据     │     │
│  │ 时间融合     │  │ PE/PB对比    │  │ 活跃地址     │     │
│  │ 曲线匹配     │  │ 护城河评分    │  │ Gas费趋势   │     │
│  │             │  │             │  │             │     │
│  │ (完全不同的  │  │ (完全不同的   │  │ (完全不同的  │     │
│  │  分析方法)   │  │  分析方法)    │  │  分析方法)   │     │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘     │
│         │               │               │             │
│         └───────────────┼───────────────┘             │
│                         │                              │
│                         ▼                              │
│              ┌─────────────────────┐                   │
│              │   统一输出接口        │                   │
│              │   (格式完全一样)      │                   │
│              └─────────────────────┘                   │
└─────────────────────────────────────────────────────────┘
```

### 2.2 插件不互相依赖

- BTC 插件不知道 NVDA 插件的存在
- 每个插件独立运行，独立输出
- 交叉判断由决策中心完成，不在插件内部

### 2.3 插件不直接读市场层或个人层

- 插件只负责分析自己的标的
- 市场环境判断由市场层提供，插件不重复做
- 个人约束由个人层提供，插件不关心

## 3. 插件生命周期

```
 draft → candidate → active → deprecated → disabled
   │         │          │          │
   │         │          │          └─ 不再使用，保留代码供复现
   │         │          └─ 正式启用，接入决策中心
   │         └─ 通过验证，等待正式启用
   └─ 开发中，仅本地测试
```

## 6. plugin.py 接口规范

### 6.1 基类定义

```python
# plugins/_template/plugin.py

from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import datetime
from typing import List, Optional

@dataclass
class TimeWindow:
    start: str               # ISO date
    end: str                 # ISO date
    anchor: Optional[str]    # 核心锚点日期
    description: str

@dataclass
class Assessment:
    signal: str              # opportunity/track/small_position/observe/high_risk/insufficient_data
    risk_level: str          # low/medium/high/extreme
    confidence: float        # 0-1
    time_window: Optional[TimeWindow]

@dataclass
class PluginOutput:
    target: str
    plugin_id: str
    plugin_version: str
    generated_at: str        # ISO datetime
    data_freshness: str      # 数据最新日期
    assessment: Assessment
    context: dict            # 插件自定义的分析细节
    reasoning: List[str]     # 人类可读的判断依据


class OpportunityPlugin(ABC):
    """机会层插件基类。所有插件必须实现此接口。"""

    @abstractmethod
    def run(self) -> PluginOutput:
        """
        执行分析，返回统一格式的结果。
        内部逻辑完全自由，输出格式必须是 PluginOutput。
        """
        pass

    @abstractmethod
    def validate_data(self) -> bool:
        """
        检查数据是否足够运行分析。
        返回 False 时，run() 应输出 signal=insufficient_data。
        """
        pass

    @abstractmethod
    def get_manifest(self) -> dict:
        """返回插件的 manifest 信息。"""
        pass
```

### 6.2 BTC 插件实现示例

```python
# plugins/btc_cycle/plugin.py

class BTCCyclePlugin(OpportunityPlugin):

    def run(self) -> PluginOutput:
        # 1. 加载数据
        prices = self._load_prices()

        # 2. 内部分析（调用现有脚本逻辑）
        annealing_result = self._run_annealing(prices)
        fusion_result = self._run_time_fusion()
        match_result = self._run_curve_matching(annealing_result)

        # 3. 综合判定
        signal, risk, confidence = self._judge(
            annealing_result, fusion_result, match_result
        )

        # 4. 输出统一格式
        return PluginOutput(
            target="BTC",
            plugin_id="btc_cycle",
            plugin_version="1.0.0",
            generated_at=datetime.now().isoformat(),
            data_freshness=prices.index[-1].isoformat(),
            assessment=Assessment(
                signal=signal,
                risk_level=risk,
                confidence=confidence,
                time_window=TimeWindow(
                    start="2025-06-01",
                    end="2025-10-01",
                    anchor="2025-08-15",
                    description="预计峰值时间窗口"
                )
            ),
            context={
                "cycle_stage": "post_peak_decline",
                "days_since_halving": 699,
                "pct_from_anchor": -43.4,
                "correlation_2017": match_result.corr_2017,
                "correlation_2021": match_result.corr_2021,
                "rmse_2017": match_result.rmse_2017,
                "rmse_2021": match_result.rmse_2021,
                "vol_scale_2017": 0.333,
                "vol_scale_2021": 0.577,
            },
            reasoning=[
                f"当前距减半已 {699} 天，处于峰值后衰减阶段",
                f"与 2017 周期退火曲线相关系数 {match_result.corr_2017:.2f}",
                f"与 2021 周期退火曲线相关系数 {match_result.corr_2021:.2f}",
                "风险等级维持高位，建议观望"
            ]
        )
```

## 7. 插件注册与发现

### 7.1 注册流程

```
开发者写好插件
     │
     ▼
plugins/xxx/manifest.yaml 存在且合法
     │
     ▼
系统启动时自动扫描 plugins/ 目录
     │
     ▼
读取所有 status != disabled 的 manifest
     │
     ▼
注册到插件注册表
     │
     ▼
决策中心知道有哪些插件可用
```

### 7.2 插件注册表

## 8. 添加新插件的完整步骤

当你未来想给 NVDA（或任何标的）写分析时，只需：

```
步骤 1:  复制 plugins/_template/ → plugins/nvda_valuation/
步骤 2:  编辑 manifest.yaml（填写标的信息、数据源、参数）
步骤 3:  实现 plugin.py 的 run() 方法（分析逻辑完全自由）
步骤 4:  写测试，本地验证输出格式正确
步骤 5:  manifest 中 status 改为 candidate
步骤 6:  运行一段时间，对比结果合理性
步骤 7:  status 改为 active，正式接入决策中心
```

**全程不需要修改主流程、不需要改决策中心代码、不需要改前端。**

## 10. 与市场层决策引擎的关系

现有的市场层决策引擎文档（V1）定义了 6 层结构（Raw Data → Facts → Scores → Policy → Recommendation → Explanation）。

这套结构 **可以整体作为 BTC 插件的内部实现**：

```
BTC 插件内部：
  Raw Data → Facts → Scores → Policy → Recommendation → Explanation
                                                          │
                                                          ▼
                                                    统一 PluginOutput
```

其他插件（如 NVDA）内部可以用完全不同的结构，只要最终输出 PluginOutput 就行。

市场层引擎的设计不浪费——它变成了 BTC 插件的"内核"。
